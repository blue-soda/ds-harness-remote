feat: make QR login the only sign-in path

Deployments that bind accounts to one external identity should not offer a
second credential that can diverge from it, so this makes the QR path exclusive.

Self-hosted Server:
- Add `DSH_SERVER_PASSWORD_LOGIN=off` (config `passwordLoginDisabled`), refusing
  POST /api/v1/auth/login with METHOD_NOT_ALLOWED for every account. The
  bootstrap account is still seeded so it can hold devices and stay reachable.
- Auto-creation for an unbound QR identity stays behind
  `DSH_SERVER_OAUTH_CREATES_ACCOUNTS=true`; accounts are capped and the login
  route stays rate limited.

Plugin:
- Remove the account/password tab from the Remote workspace picker, leaving the
  QR tab as the single sign-in choice. The provider list still drives the tabs,
  so this is one constant plus one deleted element.

Docs: describe the QR-only posture and the fact that a scan-created account has
no usable password.

Verified: server tests 28/28 including a QR-only deployment case, workspace
check clean, plugin build and tests 294 passed (5 pre-existing codex-domain
Windows platform failures).
