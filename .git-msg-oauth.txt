feat(server): WeChat QR OAuth login with a locally testable provider

Self-hosted Server:
- Add POST /api/v1/auth/oauth/qr/start, GET /api/v1/auth/oauth/qr/<qrId> and the
  provider callback, matching the plugin's existing QR contract exactly.
- Implement the WeChat Open Platform website flow (snsapi_login): the callback
  code is exchanged server-side for the user's openid, which is the stable
  subject an account is bound to. App secrets never leave the server.
- Add a mock provider for local verification without any WeChat credentials:
  the QR encodes a confirmation page on this server and the callback carries the
  subject, so the poll/bind/issue path is exercised end to end.
- Provider selection is configurable (auto/wechat/mock/off); `auto` requires both
  WeChat credentials, so a server without them simply does not advertise QR login.
- Account creation from an unknown subject is off by default: an unbound identity
  is refused and the session stays pending, so scanning a code cannot mint an
  account unless the operator opts in.
- Return redirects are pinned to the pending session's own origin, preventing an
  attacker-supplied returnTo from turning the callback into an open redirect.

Docs: document the provider configuration, the WeChat prerequisites (enterprise
verification plus an ICP-filed callback domain), the binding rules and the
registration-code alternative in apps/server/README.zh.md and AGENTS.md.

Verified: server check/build, server tests 25/25 including seven new QR OAuth
cases and a stubbed WeChat code-to-openid exchange.
