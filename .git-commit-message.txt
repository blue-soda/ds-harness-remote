feat(server): multi-account support and WeChat login entry

Self-hosted Server:
- Replace the single-account store with an account-scoped one (state v2): each
  account owns its devices and tokens, so the same deviceId may exist on several
  accounts and one account's password change only rotates its own tokens.
- Scope device discovery, pairing and presence to one account, including the
  Control gateway peer registry (account-scoped peer keys).
- Add POST /api/v1/auth/register, closed unless DSH_SERVER_REGISTRATION_CODE is
  set; the code is compared in constant time.
- Keep an unreadable or older state file safe: a v1 file is preserved as
  "<file>.v1.bak" and the server starts empty instead of failing to boot.

Plugin:
- Add a wechat OAuth provider and offer it as the only QR login entry; Zhihu and
  GitHub stay implemented but are no longer offered, controlled by a single
  ENABLED_QR_PROVIDERS list in both plugin halves.
- Update the CLI, TUI command and locale copy to the new provider set.

Docs: record the approved scope change (multi-account + WeChat entry) in
AGENTS.md and apps/server/README.zh.md, including the state-file upgrade path.

Verified: server check/build, server tests 18/18, plugin build and tests
294 passed (5 pre-existing codex-domain Windows platform failures).
